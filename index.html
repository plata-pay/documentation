Plata API

23 октября 2026 г.

Содержание

Приём платежей Plata: создание заказов, проверка статуса, отмена и уведомления об оплате. Все запросы отправляются с сервера вашего магазина. Ключ магазина передаётся в поле merchant_token.

  1. Создайте ключ в личном кабинете и сохраните его на сервере. Адрес вебхука при создании ключа указывать необязательно.
  2. Создайте заказ, указав свой order_id, и откройте покупателю полученный в ответе url.
  3. Узнайте результат одним из двух способов: опрашивайте статус заказа с сервера или, если при создании ключа указали Webhook URL, принимайте подписанные уведомления. При paid выдайте заказ один раз.

Создание заказа

POST · Content-Type: application/json

https://plata-main.dpl-payments.workers.dev/api/orders

Формат запроса

{
  "merchant_token": "YOUR_MERCHANT_TOKEN",
  "amount": "150.00",
  "order_id": "store-order-1042",
  "return_url": "https://shop.com/orders/1042"
}
ПолеОписание
merchant_tokenКлюч магазина из личного кабинета. Обязательное поле.
amountСумма в рублях: строка или число, не более двух знаков после запятой, от 0.01 до 10 000 000.
order_idИдентификатор заказа в вашем магазине: 1–128 символов, без пробелов по краям и управляющих символов. Уникален в пределах ключа. По нему же проверяется статус.
return_urlПубличный HTTPS-адрес, куда покупатель вернётся после оплаты. Возврат по этому адресу сам по себе оплату не подтверждает.

Ответ

{
  "url": "https://plata-pay.github.io/order/abcd-efgh-ijkl-mnop"
}

Новый заказ: 201. Повтор того же запроса: 200 и тот же url. Отдельного идентификатора инвойса в ответе нет — заказ всегда идентифицируется вашим order_id.

Создание идемпотентно: тот же ключ, order_id, сумма и return_url возвращают тот же url, в том числе после истечения срока. Тот же order_id с другими параметрами — ошибка 409. Неоплаченный заказ живёт 20 минут, затем получает статус expired.

Примеры запроса

const response = await fetch(
  "https://plata-main.dpl-payments.workers.dev/api/orders",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      "merchant_token": "YOUR_MERCHANT_TOKEN",
      "amount": "150.00",
      "order_id": "store-order-1042",
      "return_url": "https://shop.com/orders/1042"
    })
  }
);

const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);

Проверка статуса

Тот же адрес, метод POST и заголовок Content-Type: application/json. В запросе ровно два поля.

Формат запроса

{
  "merchant_token": "YOUR_MERCHANT_TOKEN",
  "order_id": "store-order-1042"
}

Ответ

{
  "status": "paid"
}
СтатусЗначение
pendingОжидает оплаты
paidОплачен
expiredСрок действия истёк
cancelledОтменён

Выдавайте товар или услугу только после серверной проверки статуса paid и только один раз: повторный ответ paid не должен приводить к повторной выдаче. При pending заказ ещё не оплачен — проверяйте статус по действию пользователя или с ограниченным интервалом на сервере. Заказ другого ключа по этому запросу не находится: ответ 404.

Примеры запроса

const response = await fetch(
  "https://plata-main.dpl-payments.workers.dev/api/orders",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      "merchant_token": "YOUR_MERCHANT_TOKEN",
      "order_id": "store-order-1042"
    })
  }
);

const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);

Отмена заказа

POST · Content-Type: application/json

https://plata-main.dpl-payments.workers.dev/api/orders/cancel

Формат запроса

{
  "merchant_token": "YOUR_MERCHANT_TOKEN",
  "order_id": "store-order-1042"
}

Ответ

{
  "status": "cancelled"
}

Отменить можно заказ в статусе pending. Оплаченный заказ отменить нельзя — ответ 409. Повторная отмена уже отменённого заказа возвращает тот же cancelled.

const response = await fetch(

);

Вебхуки

Вебхуки — второй способ узнавать о результатах оплаты, вместо опроса статуса. Они работают только для ключей, у которых указан Webhook URL: при создании ключа в личном кабинете или позже, в настройках уже созданного ключа. Ключ без адреса работает полностью, но уведомлений не получает — для него используйте проверку статуса.

Как это работает

Когда покупатель оплачивает заказ, Plata отправляет на адрес вашего ключа уведомление: заказ оплачен, указана сумма. Ваш сервер должен принять уведомление, сохранить результат в своей базе и только после этого ответить 200 с телом {"ok":true} — это подтверждение, что уведомление получено и обработано.

Если сервер отвечает {"ok":false}, Plata воспринимает это как отказ: уведомление не считается доставленным и будет отправлено повторно. Пустой ответ и любой другой код 2xx без явного отказа также считаются подтверждением, но для однозначности мы рекомендуем именно {"ok":true}.

Иначе говоря, Plata не считает уведомление доставленным, пока не получит подтверждение от вашего сервера. Нет подтверждения — будет повторная отправка.

Адрес должен быть публичным HTTPS на порту 443 и разрешаться в публичные IP-адреса. При смене адреса доставки на новый адрес переходят и ещё не доставленные события.

Событие

При финальном статусе заказа Plata отправляет POST на адрес ключа:

X-Plata-Event-Id: evt_0123456789abcdef0123456789abcdef
X-Plata-Timestamp: 1760000000
X-Plata-Signature: v1=<hmac-sha256-hex>
User-Agent: PlataPay-Webhooks/2.0
Content-Type: application/json
{
  "order_id": "store-order-1042",
  "amount": 150.00,
  "status": "paid"
}

Тот же формат тела — для статусов expired и cancelled. Ни секрет ключа, ни merchant_token в уведомление не входят.

Проверка подписи

Подпись — HMAC-SHA256 с секретом ключа в виде строки whsec_.... Подписывается строка timestamp + "." + event_id + "." + сырое тело запроса — заголовки X-Plata-Timestamp и X-Plata-Event-Id и точные байты полученного тела, соединённые точками.

  1. Отклоните уведомление, если метка времени отличается от вашего серверного времени больше чем на 300 секунд.
  2. Сверьте подпись сравнением за постоянное время.
  3. Обработайте событие идемпотентно: зафиксируйте X-Plata-Event-Id в своей базе с уникальным ограничением и обновите заказ ровно один раз, проверив сумму десятичной арифметикой.
  4. Верните 2xx только после фиксации в базе. Уже обработанное событие при повторе тоже получает 2xx. Рекомендуемый ответ — 200 с телом {"ok":true}. Plata читает тело ответа: {"ok":false} при статусе 2xx — это отказ, событие не считается доставленным и отправляется повторно. Пустой ответ и любой другой 2xx без явного {"ok":false} засчитываются как подтверждение.

Секрет вебхука: личный кабинет → настройки ключа.

Пример проверки подписи

Проверяйте подпись по сырому телу запроса: повторная сериализация JSON даст другую подпись, и проверка не пройдёт.

JavaScript (Node.js)

const crypto = require('node:crypto');
function verifyWebhook(secret, timestamp, eventId, rawBody, signatureHeader) {
  const expected = 'v1=' + crypto.createHmac('sha256', secret)
    .update(`${timestamp}.${eventId}.${rawBody}`, 'utf8').digest('hex');
  const a = Buffer.from(expected), b = Buffer.from(signatureHeader);
  if (a.length !== b.length) return false;
  return crypto.timingSafeEqual(a, b);
}
// rawBody — точные байты тела запроса.
// В Express: app.post('/webhook', express.raw({ type: 'application/json' }), (req, res) => {
//   const ok = verifyWebhook(SECRET, req.headers['x-plata-timestamp'], req.headers['x-plata-event-id'], req.body.toString('utf8'), req.headers['x-plata-signature']);
// });

Python

import hmac, hashlib
def verify_webhook(secret, timestamp, event_id, raw_body: bytes, signature_header: str) -> bool:
    message = f"{timestamp}.{event_id}.".encode() + raw_body
    expected = "v1=" + hmac.new(secret.encode(), message, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header)
# raw_body — сырые байты тела, а не json.dumps(payload).

Секрет показывается и обновляется в настройках ключа в личном кабинете. При обновлении секрета замените его на своём сервере: ожидающие доставки подпишутся новым секретом.

Доставка и повторы

Доставка — не реже одного раза (at-least-once): дубли возможны, поэтому идемпотентность на вашей стороне обязательна. Всего до 12 попыток, пауза начинается с 30 секунд и удваивается, но не превышает час; тайм-аут попытки — 10 секунд. Перенаправления не выполняются: адрес должен сразу отвечать 2xx. Последние 25 событий по ключу и ручной повтор неудавшихся доставок доступны в настройках ключа в личном кабинете.

Ошибки

Ошибка возвращается в формате {"error": "..."} с соответствующим HTTP-статусом.

КодЧто означает
400Неверные параметры: состав полей, сумма или return_url.
401Ключ не найден, отозван или заблокирован.
404Заказ с таким order_id у этого ключа не найден.
409Конфликт: тот же order_id с другими параметрами, отмена оплаченного заказа или ключ ещё не заведён в личном кабинете.
429Превышен лимит запросов к ключу — 60 в минуту. Соблюдайте паузу из заголовка Retry-After.
503Временная недоступность. Повторите запрос позже.

При транспортном сбое создания заказа повторяйте запрос с тем же order_id и теми же параметрами: повтор безопасен и вернёт тот же url, если первый запрос успел выполниться. Проверяйте HTTP-статус ответа перед обработкой данных.
